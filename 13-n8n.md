# 13 — n8n com Postgres e redes Docker

## O que é

O n8n é uma ferramenta de automação de fluxos. Aqui ele roda em container, com Postgres como banco e **sem nenhuma porta aberta para a internet**. O acesso ao editor é por túnel SSH.

---

## Decisões e o porquê

| Decisão | Por quê |
|---|---|
| **Postgres desde o início** | Trocar de SQLite para Postgres depois exige migrar dados |
| **`DB_TYPE=postgresdb`** | O valor `postgres` está errado: o n8n cai no SQLite sem avisar |
| **Porta em `127.0.0.1:5678`** | Porta publicada no Docker passa por cima do UFW; o loopback evita exposição |
| **Rede `dados` com `internal: true`** | O Postgres fica sem porta publicada e sem saída para a internet |
| **Versão fixada** | Evita atualização surpresa; você atualiza quando quiser |
| **Segredos gerados na VPS** | Nunca passam por chat ou Git |

---

## 1. Estrutura

```
~/n8n/
├── docker-compose.yml
└── .env          ← modo 600
```

---

## 2. Segredos

Crie o `.env` com permissão restrita e valores aleatórios:

```bash
cd ~/n8n
umask 077
cat > .env <<EOF2
N8N_VERSION=VERSAO_FIXADA
POSTGRES_PASSWORD=$(openssl rand -hex 24)
N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)
EOF2
ls -l .env     # esperado: -rw-------
```

Guarde a `N8N_ENCRYPTION_KEY` no seu gerenciador de senhas. Sem ela, as credenciais salvas no n8n não podem ser recuperadas, e não adianta trocar depois de já ter salvo credenciais.

---

## 3. docker-compose.yml (versão simplificada)

```yaml
services:
  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    container_name: n8n
    restart: unless-stopped
    ports:
      - "127.0.0.1:5678:5678"
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_DATABASE=n8n
      - DB_POSTGRESDB_USER=n8n
      - DB_POSTGRESDB_PASSWORD=${POSTGRES_PASSWORD}
      - N8N_ENCRYPTION_KEY=${N8N_ENCRYPTION_KEY}
      - N8N_SECURE_COOKIE=false
      - EXECUTIONS_DATA_MAX_AGE=168
    volumes:
      - n8n_data:/home/node/.n8n
    networks:
      - app
      - dados
    depends_on:
      - postgres

  postgres:
    image: postgres:16
    container_name: n8n-postgres
    restart: unless-stopped
    environment:
      - POSTGRES_USER=n8n
      - POSTGRES_DB=n8n
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - dados

networks:
  app:
  dados:
    internal: true

volumes:
  n8n_data:
  postgres_data:
```

Notas:

- `N8N_SECURE_COOKIE=false` só enquanto o acesso é por túnel HTTP. Com HTTPS, volta para `true`.
- `EXECUTIONS_DATA_MAX_AGE=168` apaga execuções com mais de 7 dias.

Suba:

```bash
docker compose config    # valida
docker compose up -d
```

---

## 4. Validar

```bash
# Só o loopback deve escutar na 5678, e nada na 5432
ss -tlnp | grep -E ':5678|:5432'

# O Postgres tem as tabelas do n8n?
docker compose exec postgres psql -U n8n -d n8n -c '\dt' | head

# A rede de dados está isolada? (deve falhar)
docker compose exec postgres wget -q -T 5 -O- https://example.com
```

Acesse pelo túnel: `ssh -N -L 5678:127.0.0.1:5678 vps` e depois `http://localhost:5678`.

---

## Erros que aconteceram

- **n8n sobe, mas o Postgres está vazio:** `DB_TYPE` errado (`postgres` em vez de `postgresdb`). O n8n usou SQLite sem avisar.
- **n8n para de conectar depois de mudar a senha:** a senha do Postgres só vale na primeira inicialização do volume. Mudar o `.env` depois não altera o banco. Volte o valor antigo, ou troque a senha dentro do Postgres antes.
- **Não sobrescreva um `.env` que já existe.** Isso troca a senha e a chave sem querer.
- **Credenciais ilegíveis:** a `N8N_ENCRYPTION_KEY` foi perdida ou trocada.
